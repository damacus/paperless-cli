README

Quick start, commands, and compatibility

paperless-cli is a Rust application for Paperless-ngx with three output modes: tui, markdown, and json.

Install

cargo build --release
./target/release/paperless --help

Quick start

paperless login --url https://paperless.example.com --token YOUR_TOKEN
paperless
paperless --demo
paperless --output markdown document list --query "invoice 2024"
paperless --output json search query "invoice acme"

TUI and demo mode

The two-pane browser opens while it checks the connection. After connecting, it loads documents page by page and fetches the latest task separately. A task permission error appears in the Status pane while document browsing remains available.

Use Tab to switch panes, j/k or the arrow keys to move, PgUp/PgDn to page, g/G to jump to the top or bottom, and q to quit. Press r to reload documents and the latest task and clear the Inspector cache.

The Inspector keeps up to 16 MiB of recently fetched entries for back navigation. It displays larger documents while they are selected.

For quick design and interaction feedback, run paperless --demo. Demo mode avoids real Paperless data and serves a built-in generic fixture dataset to both the CLI and the TUI.

Command surface

  • Top level: login, status, dashboard, and the default TUI
  • config: set-url, set-token
  • pdf: read, info
  • project: login, info, ping
  • document: list, get, content, upload, download, preview, thumb, edit, update, delete, search
  • tag: list, get, create, edit, delete

Network behavior

paperless status checks health and authentication with GET /api/status/. If the server returns HTTP 403, it tries GET /api/documents/?page_size=1 to check access. When the status endpoint is available, the terminal view shows component health, versions, migrations and storage. --output json includes the response from the successful probe.

paperless dashboard loads the full operational overview. It checks status and requests statistics and the complete task list concurrently.

Document downloads and bulk ZIP exports move into place after the response completes. An interrupted transfer preserves any existing destination file. New downloads on Unix use owner-only permissions.

All help paths are local and network-free.

Compatibility

  • document content <id> returns extracted text only.
  • document edit <id> --add-tag ... --remove-tag ... accepts exact tag names or IDs.
  • PAPERLESS_URL and PAPERLESS_TOKEN are supported.
  • Global compatibility flags include --json, -q/--quiet, --no-color, and -u/--url.

Release flow

The release workflow now matches the shape used in damacus/zitadel-tui: release-please manages tags and changelog updates, packaged tarballs and checksums are attached to GitHub releases, and successful releases publish the crate to crates.io.
